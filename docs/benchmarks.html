Repeated baseline complete. Every requested trial was evaluated. Thirty-nine repairs survived the scenario verifier, service restart, and host reboot. Six attempts failed: four lost pre-existing backlog and two reached the agent timeout.

Model summary

Each model ran each scenario three times through Claux on August 8, 2026. This remains a small sample, but repetition exposed reliability differences hidden by the earlier perfect smoke run.

GLM produced the most repairs and the fastest overall median. DeepSeek and GLM cost roughly 1.2 and 1.3 cents per durable repair. HY3's known cost was lower, but one timed-out trial reported no usage, so its total is a lower bound. Reliability is part of the price: the cheapest invocation is not necessarily the cheapest successful repair.

The Redis incident did the most useful separating. Four attempts repaired future job processing but failed to recover the controller-owned backlog. One GLM attempt explicitly deleted the stale queue. The service looked healthy afterward, but customer work was gone, so the verifier rejected it. The poison-pill incident produced the other model failure when DeepSeek reached the 900-second limit.

One timeout needed a post-run classification correction. HY3's second Redis attempt ran for 934 seconds and exited through SSH with status 255. The raw summary left it uncategorized even though the configured limit was 900 seconds. Replaybook now recognizes that SSH timeout path; the result above counts it as an agent timeout.

What counts as current

Current results use host harness v5 and the scenario versions shown above. Harness v5 keeps the oracle and verifier outside the model VM and separates unavailable provider or harness attempts from evaluated model failures. Results from older harnesses remain available under History, but are not mixed into this comparison.
