What Replaybook measures

Replaybook evaluates whether an agent can diagnose and durably repair a running production-style system. We score the state left behind after the agent stops, not the confidence or polish of its final answer.

Choose a scenario to see one benchmark in isolation, or use Models, Providers, and Compare to inspect compatible evidence.

The scoring contract

What counts as a pass

01

Repair the live system

User-facing behavior must recover without replacing the host.

02

Preserve existing work

Queued jobs and controller-owned state cannot be discarded.

03

Survive service restart

Temporary processes and in-memory workarounds must disappear safely.

04

Survive host reboot

Only durable changes to the deployed system count.

How the layers fit together

The controller builds a disposable NixOS VM and owns the incident lifecycle, timeout, restart, reboot, oracle, and verifier. The host harness is this scoring boundary. An agent harness, such as Claux or OpenCode, drives the model inside the VM. Provider and billing information are recorded separately when known.

The oracle and verifier stay outside the model VM. The agent receives the incident and normal Linux tools, but never the answer key. Every trial retains a sanitized transcript and immutable execution snapshot.

Evaluated, failed, and unavailable

An evaluated trial reached the agent and verifier. A failed repair counts against that complete model, harness, and provider lane. Authentication failures and provider or harness errors before meaningful inference are unavailable; they remain visible but are excluded from the pass-rate denominator.

After work begins, interruptions, protocol errors, policy rejections, and runtime failures remain evaluated execution-lane failures with their original category.

When results are comparable

Comparisons lock the scenario and verifier versions, host harness, timeout, agent harness, tools, permissions, tier, attempt count, and provenance. Different providers or harnesses are companion cohorts, not silently pooled totals.

Benchmark tiers

SmokeQualify cheaply

Three representative scenarios, one attempt each.

CoreCompare routinely

Eight representative incidents, three attempts each.

FullMeasure broadly

Every stable incident, three attempts each.

FrontierTest real systems

Resource-heavy, longer-deadline deployments.

Tiers overlap by design, but remain separate comparison boundaries.
